# 2026-10-01: `www` was down for 18+ days and nobody saw

**What happened:** `https://www.theimmortalvibes.com/` returned Cloudflare 522 for at least 18 days. The apex
returned 200 the whole time.

**Root cause:** the `www` DNS record pointed at the Pages project and was proxied, so the DNS half looked done.
But `www` was never attached to the Pages project's custom domains, so Cloudflare had no origin for that
hostname. A successful DNS record made it look finished.

**Why nobody noticed:** uptime monitoring probed only the apex and reported "HTTP 200" every day.

**Fix:** a zone-level Single Redirect sends `www` → apex with a 301, keeping path and query string. It runs
before the origin fetch, so Pages never needs to serve `www`. Monitoring was extended to probe `www` too.

**Side finding the same day:** the "86% of checkouts fail at payment" number was wrong. `POST /api/checkout`
creates the PaymentIntent when the visitor reaches the payment form, before any card is entered, so
`requires_payment_method` means "reached the form", not "payment failed". A full live pass showed checkout
working end to end.

**Rules produced:** IV-1, IV-8, IV-9, IV-10.
